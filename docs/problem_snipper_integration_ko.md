# ProblemSnipper 기반 최종 PDF 병합 동작 개요

## 개입 지점
- `pdf_creator.py`의 `PDFCreator` 클래스가 족보 중심(jokbo-centric) 모드 등 최종 PDF 병합 단계를 담당합니다.
- 이번 수정에서는 동일 파일 내에 `ProblemSnipper` 프로토타입을 불러와, **족보 원본에서 개별 문항 이미지를 정밀하게 잘라 재구성**하는 과정을 추가했습니다.
- 즉, 분석 파이프라인의 마지막 "PDF 생성" 단계에서만 새로운 잘라내기 로직이 작동하며, 그 이전 단계(분석, 매칭 등)는 그대로 유지됩니다.

## 처리 흐름
1. `ProblemSnipper`가 제공하는 `extract()`를 통해 각 족보 PDF에서 문항별(`ProblemSegment`) 좌표 정보를 미리 계산하여 캐싱합니다.
2. PDF 병합 시 특정 문항(예: 1번, 2번 등)을 렌더링해야 하면 `ProblemSegment` 목록에서 **문항 번호, 페이지 위치, 텍스트 일부**를 기반으로 가장 유력한 세그먼트를 선택합니다.
3. 선택된 세그먼트의 `page_spans` 좌표를 사용해, `PyMuPDF`가 원본 PDF에서 해당 영역만을 잘라 새 페이지로 렌더링합니다.
4. 잘라낸 결과가 비어 있으면 자동으로 기존(legacy) 방식으로 되돌아가므로, 호환되지 않는 PDF도 안전하게 처리합니다.

## 공학적 세부 메커니즘
- **문항 매칭**: `_select_snipper_segment()`는 `ProblemSegment`의 표시 번호(`display_number`), 메타데이터(`metadata['question_number']`), 페이지 번호 등을 정규화하여 비교합니다. 문자열 내 숫자만 추출하여 비교하기 때문에 "1단", "2단"처럼 접미사가 붙어 있어도 인식합니다.
- **좌표 보정**: `_clip_rect_with_margin()`이 각 문항에 포함된 다중 `rect`를 통합하고, 작은 여백(6pt)을 둘러서 잘림을 방지합니다.
- **렌더링**: `_render_snipper_segment()`는 선택된 세그먼트의 모든 페이지 범위를 순회하며, `show_pdf_page()`로 원본 페이지를 클리핑하여 새로운 임시 PDF로 추출합니다.
- **캐싱**: `_snipper_segment_cache`를 통해 같은 족보 파일에 대한 `ProblemSnipper` 분석을 한 번만 수행하고, 다중 문항 병합 시 재사용하여 성능을 확보합니다.

## 세로 단(멀티 컬럼) 레이아웃 처리
- `ProblemSnipper`는 페이지의 텍스트 블록(`block_id`) 정보를 그대로 보존하여 `page_block_rects`에 저장합니다. 한 페이지가 여러 단(세로 컬럼)으로 나뉘어 있고 한 가로선에 여러 문제가 붙어 있어도 각 문제는 자신의 블록 좌표만 갖습니다.
- `pdf_creator.PDFCreator`는 해당 블록 좌표를 우선적으로 사용해 클리핑 영역을 계산합니다. 즉, 문제와 무관한 다른 단(column)의 영역은 잘라내기에 포함되지 않으므로, 가로 방향으로 이웃한 다른 문제가 결과 PDF에 섞이지 않습니다.
- 만약 문제 텍스트와 선택지가 서로 다른 블록에 존재하는 복합 형태라면, 각 블록의 좌표를 모두 합쳐 하나의 영역으로 병합하여 **필요한 부분만** 남기고 생성합니다.

## 단계형 문항(1단, 2단 등) 번호 파싱
- 문항 번호 파싱 시 정규식으로 숫자를 추출하므로 "1단", "2단", "3단"과 같이 한글/영문 접미사가 있는 단계형 표기도 정상적으로 매칭됩니다.
- 동일 숫자를 가진 여러 세그먼트가 존재할 경우에는 페이지 거리, 세그먼트 인덱스를 고려하여 가장 가까운 항목을 선택하므로, 난이도 단계별(1단, 2단) 구성에서도 정확도가 유지됩니다.

## 예시
- 예를 들어 jokbo PDF의 12쪽 좌측 단(column)에 "1단-2번" 문항이 있고, 우측 단에는 다른 문제가 나열되어 있더라도:
  1. `ProblemSnipper.extract()`는 해당 문항을 포함하는 좌표를 `ProblemSegment`로 저장합니다.
  2. 병합 시 `question_number="1단-2"`, `jokbo_page=12`가 전달되면 `_select_snipper_segment()`가 숫자 "12"와 페이지 정보를 정규화하여 매칭합니다.
  3. `_render_snipper_segment()`가 좌측 단에 해당하는 블록 좌표만 모아 클리핑한 PDF 조각을 만들고, 최종 리포트에 삽입합니다.
- 만약 문항 좌표가 감지되지 않으면 기존 방식(페이지 전체 또는 대략적 영역 추출)이 자동으로 사용됩니다.

## 기대 효과
- 원본 PDF 레이아웃 변화에 덜 민감한 정밀 클리핑이 가능해졌으며,
- 단계형(1단, 2단 등) 문항과 복수 페이지에 걸친 문제도 안정적으로 잘라낼 수 있습니다.
